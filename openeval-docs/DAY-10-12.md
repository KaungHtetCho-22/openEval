# Days 10–12 — Async Runner + Batch Evaluation

## Goal
Build an async version of the eval runner that evaluates multiple cases in parallel. This is what makes OpenEval production-usable vs a toy. Evaluating 100 cases sequentially might take 5 minutes. In parallel: 30 seconds.

---

## Why this matters for virality
When someone benchmarks OpenEval against DeepEval and shows "100 cases in 28 seconds vs 4 minutes" — that screenshot alone drives stars. Performance is a feature.

---

# DAY 10 — Async Runner Core

## Step 1 — async_runner.py

Ask Claude: **"Write openeval/async_runner.py — an async version of the eval loop"**

Tell Claude:
- Function: `async def arun(model_fn, dataset, scorers, pass_threshold=0.7, concurrency=10) -> EvalSummary`
- `model_fn` can be either sync or async callable (detect with `asyncio.iscoroutinefunction`)
- Use `asyncio.Semaphore(concurrency)` to limit concurrent calls
- Use `asyncio.gather()` to run all cases in parallel
- Show a live progress bar using `rich.progress`
- Same return type as sync `run()` — `EvalSummary`

Concurrency behavior:
- Default 10 concurrent calls (safe for most APIs)
- User can set `concurrency=1` to go sequential (useful for rate-limited APIs)
- User can set `concurrency=50` for high-throughput local models

# DAY 11 — Batch Evaluation

## Step 5 — batch.py

Ask Claude: **"Write openeval/batch.py — batch evaluation utilities"**

Tell Claude:
- `batch_run(model_configs, dataset, scorers) -> dict[str, EvalSummary]`
  - Evaluates multiple models against the same dataset
  - `model_configs` is a dict: `{"gpt-4o": openai_adapter("gpt-4o"), "llama3": ollama_adapter("llama3")}`
  - Returns a dict of model_name → EvalSummary
- `compare(summaries: dict[str, EvalSummary]) -> ComparisonTable`
  - Takes the output of `batch_run` and builds a comparison table
  - `ComparisonTable` has a `.to_rich_table()` and `.to_html()` method
  - Shows each model's pass rate and mean score per scorer side by side

This is the feature for the benchmark README section.
