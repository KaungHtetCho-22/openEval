# Days 8–9 — GitHub Action + HTML Report Generator

## Goal
Day 8: Official GitHub Action that runs evals on every PR and posts results as a PR comment.
Day 9: HTML report generator — a beautiful self-contained file with score breakdowns.

These two features are the primary viral growth drivers. Build them carefully.

---

# DAY 8 — GitHub Action

## Why this is the most important feature
Every repo that uses this Action puts `openeval` in their public workflow files. GitHub indexes these. Developers searching for eval solutions find your Action. This is how tools spread silently — through other people's repos.

---

## Step 1 — Action folder structure

Create:
```
openeval-action/
├── action.yml
├── entrypoint.py
└── README.md
```

---

## Step 2 — action.yml

Ask Claude: **"Write openeval-action/action.yml — the GitHub Action definition"**

Tell Claude the action should:
- Name: "OpenEval — LLM Evaluation"
- Be a Docker action (most reliable for Python)
- Inputs:
  - `dataset`: path to JSONL/CSV dataset file (required)
  - `model`: model string like `ollama:llama3.2` (required)
  - `suite`: built-in suite name (optional, alternative to dataset)
  - `threshold`: pass threshold, default "0.7"
  - `fail_on_threshold`: whether to fail the CI if below threshold, default "true"
  - `openai_api_key`: OpenAI API key (optional, secret)
  - `anthropic_api_key`: Anthropic API key (optional, secret)
- Outputs:
  - `pass_rate`: the overall pass rate
  - `passed`: "true" or "false"
  - `report_path`: path to generated HTML report

---

## Step 3 — entrypoint.py

Ask Claude: **"Write openeval-action/entrypoint.py — the script that runs inside the GitHub Action"**

Tell Claude it should:
1. Read inputs from environment variables (GitHub Actions passes inputs as `INPUT_*` env vars)
2. Run the eval using OpenEval
3. Generate an HTML report
4. Post results as a PR comment using the GitHub API (use `GITHUB_TOKEN` env var)
5. Set output variables using `$GITHUB_OUTPUT`
6. Exit with code 1 if pass rate is below threshold AND `fail_on_threshold` is true

PR comment format:
```
## OpenEval Results

| Metric | Value |
|--------|-------|
| Pass Rate | 87.5% ✅ |
| Total Cases | 16 |
| Passed | 14 |
| Failed | 2 |

<details>
<summary>View full breakdown</summary>

[table of per-case results]

</details>
```

## Step 4 — Action README

Ask Claude: **"Write openeval-action/README.md — how to use the GitHub Action"**

Should include:
- Quick start (minimal workflow YAML people can copy-paste)
- Full configuration example
- How to use with OpenAI/Anthropic (secrets setup)
- How to use with Ollama (note: needs self-hosted runner)

Minimal example to show:
```yaml
# .github/workflows/eval.yml
name: LLM Eval
on: [pull_request]

jobs:
  eval:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: your-username/openeval-action@v1
        with:
          suite: hallucination
          model: openai:gpt-4o-mini
          threshold: "0.8"
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
```

# DAY 9 — HTML Report Generator

## Why this matters
A beautiful self-contained HTML report that you can open in a browser, share with your team, or attach to a PR. This is the "wow" feature in demos.

---

## Step 6 — report.py

Ask Claude: **"Write openeval/report.py — an HTML report generator"**

Tell Claude:
- Function: `generate_report(summary: EvalSummary, output_path: str, title: str = "OpenEval Report")`
- Generates a single self-contained HTML file (no external CSS/JS dependencies)
- Inline all CSS and JS
- Report should include:
  - Header with title, model name, date, pass rate as big hero number
  - Summary stats: total cases, passed, failed, mean scores per scorer
  - Score distribution chart (simple CSS bar chart, no JS library needed)
  - Full results table with: input, expected output, actual output, score per scorer, pass/fail
  - Color coding: green rows for pass, red for fail
  - Collapsible rows for long inputs/outputs
- Make it genuinely beautiful — this will be screenshotted
